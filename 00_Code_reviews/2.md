# Original Code

```python
import time

def check_and_increment_login_attempts(user_id, client_payload):
    # Expected payload: {"ip_address": "192.168.1.50", "timestamp": 1718912345}

    # 1. Base validation
    ip = client_payload["ip_address"]

    # Generate a tracking key for the distributed cache
    rate_limit_key = f"rate:{user_id}:{ip}"

    # 2. Fetch current tracking value from cache
    # cache.get() returns a string value or None if key expired/missing
    current_attempts = cache.get(rate_limit_key)

    if current_attempts is not None:
        attempts_count = int(current_attempts)

        # 3. Check threshold limit (Max 5 attempts allowed)
        if attempts_count >= 5:
            return {"status": "blocked", "message": "Too many attempts"}, 429

        # Increment value by 1
        new_count = attempts_count + 1
        cache.set(rate_limit_key, str(new_count))
    else:
        # First failed attempt: Initialize count and set a 60-second window expiration
        cache.set(rate_limit_key, "1")
        cache.expire(rate_limit_key, 60)

    return {"status": "allowed"}, 200
```

# Issues Found

## Critical

### Issue 1: Non-Atomic Cache Update

**Severity:** Critical

**Category:** Correctness / Scalability

#### Description

The cache update uses a `get()` → increment → `set()` sequence, which is not atomic.

#### Impact

Concurrent login requests can overwrite each other's updates, allowing more than the intended five login attempts.

#### Recommendation

Use an atomic cache operation such as Redis `INCR`, a Lua script, or compare-and-swap (CAS).

#### Code Reference

```python
current_attempts = cache.get(rate_limit_key)
...
cache.set(rate_limit_key, str(new_count))
```

---

### Issue 2: Trusting Client-Supplied IP Address

**Severity:** Critical

**Category:** Security

#### Description

The IP address is taken directly from the request payload.

```python

```

An attacker can modify this value to bypass rate limiting.

#### Impact

The rate limiter becomes ineffective.

#### Recommendation

Retrieve the client IP from the server or reverse proxy instead of trusting user input.

# Complete Refactored Code

```python
from typing import Dict, Tuple

MAX_LOGIN_ATTEMPTS = 5
WINDOW_SECONDS = 60


def check_and_increment_login_attempts(
    user_id: str,
    client_ip: str,
) -> Tuple[Dict[str, str], int]:
    """
    Checks and increments failed login attempts for a user/IP combination.

    Assumes the cache supports atomic increment operations.
    """

    if not client_ip:
        return {"status": "error", "message": "Missing IP address"}, 400

    cache_key = f"rate:{user_id}:{client_ip}"

    try:
        attempts = cache.incr(cache_key)

        if attempts == 1:
            cache.expire(cache_key, WINDOW_SECONDS)

    except Exception:
        return {"status": "error", "message": "Rate limiter unavailable"}, 500

    if attempts > MAX_LOGIN_ATTEMPTS:
        return {
            "status": "blocked",
            "message": "Too many attempts",
        }, 429

    return {"status": "allowed"}, 200
```
