# Original Code

```java
public static void readFile(String filePath) throws Exception {

    FileInputStream fis = new FileInputStream(filePath);

    int i;

    while ((i = fis.read()) != -1) {
        System.out.print((char) i);
    }

}
```

# Review Findings

## 1. Correctness

### Issues

- No validation for `filePath`.
- Empty or null file path may cause exceptions.
- No validation whether the file exists.
- Reads one byte at a time, which is inefficient for large files.
- Uses `FileInputStream`, which is intended for binary data, while printing characters.

### Recommendation

- Validate input.
- Check file existence.
- Use `BufferedReader` or `Files.newBufferedReader()` for text files.
- Read line-by-line or using a buffer.

---

## 2. Error Handling

### Issues

Throws generic

```java
throws Exception
```

This hides the actual exception.

No exception handling.

No logging.

### Recommendation

Throw specific exceptions like

```java
IOException
```

or

```java
FileNotFoundException
```

Handle exceptions where appropriate and log meaningful messages.

## 3. Performance

### Issues

Reads

```java
fis.read()
```

one byte at a time.

This results in excessive system calls for large files.

### Recommendation

Use

```java
BufferedInputStream
```

or

```java
BufferedReader
```

Example

```java
BufferedReader reader =
    Files.newBufferedReader(path);
```

or

```java
byte[] buffer = new byte[8192];
```

## 4. Security

### Issues

No validation of file path.

Possible path traversal if file path comes from user input.

Example

```
../../etc/passwd
```

No authorization check.

### Recommendation

- Validate file location.
- Restrict access to approved directories.
- Avoid exposing arbitrary file reads.

---

## 5. Maintainability

### Issues

Method performs

- Open file
- Read file
- Print file

Mixes I/O and presentation.

Method name

```java
readFile()
```

is acceptable, but returning the file contents instead of printing would make it more reusable.

### Recommendation

Separate responsibilities.

```text
openFile()

readContents()

displayContents()
```

## 6. Coding Standards

### Issues

Missing

- JavaDoc
- Null validation
- Logging
- Specific exception type

Uses

```java
System.out.print()
```

instead of a logging framework.

## 7. Resource Management

### Critical Issue

FileInputStream is never closed.

```java

```

causes resource leakage.

Eventually

- File descriptors
- Native handles

### Recommendation

Use

```java

```


```java

```

# Revised Code (Using BufferedReader)

```java
import java.io.BufferedReader;
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.Objects;

public class FileReaderUtil {

    /**
     * Reads a text file and prints its contents.
     */
    public static void readFile(String filePath) throws IOException {

        Objects.requireNonNull(filePath, "File path cannot be null.");

        if (filePath.isBlank()) {
            throw new IllegalArgumentException("File path cannot be empty.");
        }

        Path path = Path.of(filePath);

        if (!Files.exists(path)) {
            throw new IOException("File not found: " + filePath);
        }

        try (BufferedReader reader = Files.newBufferedReader(path)) {

            String line;

            while ((line = reader.readLine()) != null) {
                System.out.println(line);
            }
        }
    }
}
```

# Code Review Summary

- Close resources properly.
- Use specific exceptions.
- Validate input.

- Add documentation.
- Improve security for user-supplied paths.

# Interview Takeaways

A senior engineer should immediately identify:

- Resource leak due to unclosed `FileInputStream`
- Use of generic `Exception`
- Missing null and path validation
- Inefficient byte-by-byte reading
- Wrong abstraction for text files (`BufferedReader` is more appropriate)
- Missing logging
- Path traversal risk if the path is user-controlled
- Lack of separation of concerns
- Missing test coverage

These observations demonstrate senior-level code review skills across correctness, performance, resource management, security, maintainability, and Java best practices.
